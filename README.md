# Інформаційна система контролю стану музейних експонатів

Курсова робота з дисципліни «Кросплатформене програмування», варіант №24.

Система допомагає вести облік музейних експонатів, фіксувати результати їх оглядів і керувати заявками на консервацію. Для кожної заявки сервер розраховує інтегральний показник ризику та контролює чотиристанний життєвий цикл. Дані зберігаються в MySQL, серверна частина працює як web-застосунок у Tomcat і віддає дані у форматі JSON, а користувач працює через графічний клієнт на JavaFX.

**Основні сутності:** експонат (`Exhibit`), огляд (`Inspection`), заявка на консервацію (`ConservationRequest`), фахівець (`Specialist`).

**Інтегральний показник ризику:** `I = 0,40·F1 + 0,35·F2 + 0,25·F3`, де F1 — чутливість матеріалу, F2 — тяжкість пошкодження, F3 — значущість експонування (усі в діапазоні 0–100).

**Життєвий цикл заявки:** `NEW → ASSESSED → WORKS → COMPLETED` (НОВА → ОЦІНЕНО → РОБОТИ → ЗАВЕРШЕНО). Пропуски станів і повернення назад заборонені.

Через JavaFX-клієнт можна переглядати дані, виконувати CRUD для всіх сутностей, змінювати стан заявки та імпортувати каталог експонатів із CSV-файлу.

## Підготовка бази даних

1. Запустіть MySQL (наприклад, модуль MySQL у XAMPP Control Panel) і переконайтеся, що сервер доступний.
2. Відкрийте phpMyAdmin на рівні сервера (без вибраної бази), вкладка **Імпорт**, виберіть кореневий файл `database.sql` (кодування `utf-8`) і виконайте його. Скрипт сам видаляє стару базу `museum_exhibits` і створює її заново.
3. Перевірте, що в базі `museum_exhibits` є чотири таблиці: `exhibit`, `inspection`, `specialist`, `conservation_request`, а в `exhibit`, `inspection` і `specialist` є початкові записи (3, 3 і 2).
4. Параметри підключення (`URL`, `USER`, `PASSWORD`) задані в `server/src/main/java/ua/edu/nupp/kpp/server/DBUtil.java`. Якщо ваша локальна MySQL використовує інші значення, змініть їх у цьому файлі локально; власні паролі до репозиторію не додавайте.

## Запуск сервера

Усі команди Maven виконуються з каталогу `server`.

```
cd server
mvn clean test
mvn clean package
```

Після збірки з'явиться файл `server/target/museum-exhibits-server.war`. Скопіюйте його до каталогу `webapps` Apache Tomcat 9.x і запустіть Tomcat.

Перевірка запуску: у браузері відкрийте `http://localhost:8080/museum-exhibits-server/exhibits`. Має повернутися JSON-масив експонатів. Аналогічно доступні `/inspections`, `/requests` і `/specialists`. Якщо Tomcat показує помилку розгортання або повертається 404, перевірте назву WAR-файлу (вона визначає контекст) і те, що MySQL запущена та база створена.

## Запуск JavaFX-клієнта

Перед запуском клієнта мають працювати MySQL і Tomcat із розгорнутим серверним WAR (клієнт не працює автономно).

```
cd client
mvn javafx:run
```

Клієнт звертається до сервера за адресою `http://localhost:8080/museum-exhibits-server` (константа `BASE` у `HttpMuseumExhibitsClient.java`). Якщо клієнт повідомляє про помилку підключення або 404, спершу перевірте, що Tomcat запущений і контекст WAR збігається з цією адресою.

## Тестування

JUnit 5-тести серверної частини розташовані в `server/src/test/java` і запускаються командою:

```
cd server
mvn clean test
```

Тести перевіряють предметні правила без запуску JavaFX: розрахунок інтегрального показника (три контрольні набори F1, F2, F3 і відхилення фактора поза діапазоном 0–100), дозволені й заборонені переходи станів заявки та валідацію даних експоната й огляду. Усього 10 тестів.

## CSV-імпорт

- **Файл:** `client/sample-data/exhibits.csv`; шлях `sample-data/exhibits.csv` рахується від робочого каталогу `client`, тому клієнт слід запускати з цього каталогу командою `mvn javafx:run`.
- **Формат:** кодування UTF-8, роздільник `;`, шість полів, перший рядок містить заголовок: `inventory_code;name;material;hall;material_sensitivity;exhibition_significance`.
- **Дії користувача:** запустіть MySQL, Tomcat і клієнт, відкрийте вкладку **Експонати**, натисніть **Імпортувати CSV** та спостерігайте за індикатором прогресу. Імпорт виконується у фоновому потоці (`javafx.concurrent.Task`), інтерфейс не блокується. Записи додаються через HTTP-запити до сервера, а не прямим JDBC-з'єднанням.
- **Обмеження:** спеціальної перевірки дублікатів немає, тому повторний імпорт того самого файлу додасть ті самі експонати ще раз. Некоректний заголовок або нечислове значення зупиняє імпорт із повідомленням. Перед повторною перевіркою імпорту відновіть базу, знову виконавши `database.sql`.
